# Zod

_2026.11.13._

> 데이터가 사전에 정한 조건에 맞는지 검사하고, 자동 타입 생성까지 해 주는 라이브러리

> **왜 사용해야 하는가?**  
> 일반적으로 데이터를 검사하는 경우는 크게 두 가지이다.
>
> 1. 코드를 작성할 때: 값의 **종류와 구조**를 검사 (타입 정의 - TypeScript가 검사)
> 2. 실제 데이터(사용자 입력값, 서버 응답 등)가 들어올 때: 값의 **종류와 구조, 내용**까지 검사 (조건문)
>
> 즉 Zod를 사용하지 않을 경우 1과 2를 각각 작성해야 하나, Zod는 2 검사를 수행하며 1에 필요한 타입 정의까지 함께 해 준다!

> **스키마(Schema)**  
> 데이터가 지켜야 할 조건(종류, 구조, 내용(길이, 형식 등))을 정의해 둔 것.

## `z.object`

- 객체 형태 데이터의 스키마를 만드는 함수.
- 객체의 각 필드별 스키마를 넣은 하나의 객체를 인자로 넣고, 최종 스키마 하나를 반환한다.

```ts
import * as z from "zod";
/* z. 함수 사용을 위해 z를 import함(Zod 4 공식 문서 방식) */

const signupSchema = z.object({
  email: z
    .string()
    .trim()
    .min(1, "이메일을 입력해주세요.")
    .pipe(z.email("이메일 형식이 올바르지 않아요.")),
  nickname: z
    .string()
    .trim()
    .min(2, "닉네임은 2~10자로 입력해주세요.")
    .max(10, "닉네임은 2~10자로 입력해주세요."),
  password: z
    .string()
    .min(8, "비밀번호는 8~64자로 입력해주세요.")
    .max(64, "비밀번호는 8~64자로 입력해주세요."),
  passwordConfirm: z.string().min(1, "비밀번호를 한 번 더 입력해주세요."),
});
```

### `const signupSchema = z.object({...});`

- `{...}`: 객체의 각 필드별 스키마가 정의된 하나의 객체.

### `email: z.string().trim().min(1, ...)...`

- `필드명: z.타입().조건().조건()...` 형태.
- `z.string()`: 문자열 타입이어야 한다.
- `.trim()`: 입력값 앞뒤의 공백을 제거한다.
- `.min(1, ...)`: 최소 1 글자 이상이어야 함, 미달 시 두 번째 인자의 문장을 에러 메시지로 출력.
- `.max(10, ...)`: 최대 10 글자 이하여야 함, 초과 시 두 번째 인자의 문장을 에러 메시지로 출력.
- `.pipe(z.email(...))`: 앞의 조건 검사들을 통과한 값을 `z.email()`에 넘겨서 형식 검사 후, 미충족 시 인자의 문장을 에러 메시지로 출력

## `.refine`

- 스키마의 검사 조건을 직접 만들어 추가하는 함수
- `.trim()`, `.min()`과 같이 Zod에 사전 정의되어 있는 조건들 외에 추가로 필요한 검사 조건이 있을 때 사용한다.

```ts
const signupSchema = z
  .object({
    /* email, nickname 생략 */
    password: z.string().min(8, "...").max(64, "..."),
    passwordConfirm: z.string().min(1, "비밀번호를 한 번 더 입력해주세요."),
  })
  .refine((values) => values.password === values.passwordConfirm, {
    path: ["passwordConfirm"],
    error: "비밀번호가 일치하지 않아요.",
  });
```

### `.refine((...) => ..., {...})`

- `(...) => ...`: 검사 함수. `true` 또는 `false` 반환
- `{...}`: 검사 함수의 반환값이 `false`일 때의 설정을 담은 객체

### `(values) => values.password === values.passwordConfirm`

- `values`라는 이름으로 검사할 객체 데이터 전체를 받아서 `password`와 `passwordConfirm` 필드값이 같은지 확인한다.

> **`===` 사용 이유**  
> `==`는 비교 대상의 타입이 다르면 자동으로 변환해서 비교한다. 즉 값이 제대로 비교되지 않고 예상과 다른 결과가 나올 수 있다.  
> `===`은 타입이 다르면 바로 `false`를 반환하기 때문에 관례상 `===`를 사용한다.

### `{path: ["..."], error: "...",}`

- `path: ["passwordConfirm"]`: 검사가 실패했을 때 에러로 처리할 필드명을 지정한다.
- `error: "..."`: 검사가 실패했을 때 출력할 에러 메시지를 지정한다.

> **Zod는 검사에 실패하면 "어느 필드가 틀렸는지" 함께 알려준다.**  
> Zod는 검사에 실패한 필드와 에러 메시지를 함께 반환하고, 화면에서는 이를 보고 적절한 위치에 에러 메시지를 띄운다.  
> 각 필드별 조건에서 검사가 실패할 경우(ex: `email: z.string().min(1, ...)`) Zod가 바로 필드를 알 수 있다.  
> 그러나 `.refine`의 경우 특정 필드 자리가 아니라 `z.object` 전체 뒤에 붙기 때문에, 에러가 발생해도 Zod가 어느 필드 에러인지 바로 알 수 없다.  
> 그러므로 `path: ["..."]`에 에러로 처리할 필드명을 넣어, Zod가 에러 발생 필드를 파악할 수 있도록 한다!  
> (객체 전체 에러로 처리해도 되는 상황이라면 `path` 지정을 생략할 수 있다.)

## `z.infer`

- 스키마를 기반으로 TypeScript 타입을 자동으로 만들어주는 제네릭 타입.
- 글 상단의 필요성 파트에서 정리한, 1번 검사(코드 작성 시)에 필요한 타입 정의를 해 준다!

```ts
type SignupForm = z.infer<typeof signupSchema>;
```

### `z.infer<typeof signupSchema>;`

- `z.infer<...>`는 인자로 타입을 받기 때문에 `typeof`로 `signupSchema`가 정의되며 자동으로 정해진 스키마 타입을 꺼내 인자로 넣는다.

> `typeof`로 꺼낸 스키마 타입은 데이터의 타입으로 쓸 수 없는 형태이기 때문에(ex: `ZodString`) `z.infer<...>`에 넣어 적절한 데이터 타입 형태로(ex: `string`) 변환해주어야 한다.

```ts
type SignupForm = {
  email: string;
  nickname: string;
  password: string;
  passwordConfirm: string;
};
```

> 위에서 `z.infer<...>`로 만든 `SignupForm`의 실제 타입. (이해를 돕기 위한 예시 코드이지 실제로 이렇게 중복 선언하지 않는다!)

- 스키마의 `z.타입()` 부분만 타입에 반영되고 `.min()`, `.refine()` 같은 내용 검사 조건은 별도 반영되지 않는다.
- 추후 스키마의 필드가 변경되면 `SignupForm` 타입도 그에 맞게 자동으로 갱신된다.

```tsx
useForm<SignupForm>({ ... });
```

> 생성한 타입을 실제 사용하는 예시 코드.

- `useForm`: 폼의 입력값, 검사, 에러, 제출을 관리하는 React Hook Form의 훅.
- `<SignupForm>`으로 폼 데이터의 타입을 지정하면, 해당 타입과 다르게 작성한 코드를 TypeScript가 코드 작성 단계에서 에러로 표시한다.

## 전체 흐름 정리

- `z.object`로 객체 데이터의 필드별 검사 조건을 정의해 스키마를 만든다.
- 사전 정의된 조건으로 부족한 검사는 `.refine`으로 직접 정의 및 추가한다.
- `z.infer`로 스키마에서 TypeScript 타입을 만들어, 코드 작성 단계의 타입 검사에 사용한다.
- 앱 실행 중에는 스키마가 실제 데이터를 검사하고, 실패 시 필드별 에러 메시지를 반환한다.
